# 第二阶段类型3和类型4任务偏差分析

## 问题描述

从推理结果和评估日志可以看到，模型在类型3（区域描述）和类型4（层级分类）任务上表现不佳：

### 类型3任务（区域描述）

**期望输出格式**：纯文本描述
```
"阳性宫颈细胞，来自基底层，可见核深染、核不规则、核浆比高。"
```

**实际模型输出**：
```
"<ground>左下角有一个紫色的细胞</ground><objects><region0></objects><|im_end|>"
```

**问题**：
- ❌ 模型输出了定位任务的格式（`<ground><objects>`），而不是纯文本描述
- ❌ 描述内容不准确（"紫色的细胞"、"左下角"等，不符合医学描述规范）
- ❌ 模型混淆了任务类型，把区域描述当成了定位任务

### 类型4任务（层级分类）

**期望输出格式**：只输出层级名称
```
"中间层"
```

**实际模型输出**：
```
"上皮细胞簇"
```

**问题**：
- ✅ 格式正确（纯文本，无定位标签）
- ❌ 答案错误（预测"上皮细胞簇"，真实是"中间层"）

## 根本原因分析

### 1. 任务格式混淆（主要原因）

**问题**：模型在第一阶段只学习了定位任务（类型1），输出格式是`<ground>...<objects>`。第二阶段虽然加入了类型3和类型4，但模型仍然倾向于输出熟悉的定位格式。

**证据**：
- 从日志可以看到，类型3任务经常输出`<ground>...<objects>`格式
- 模型可能将"描述图中这个区域"理解为"定位这个区域"

**训练数据分布**：
- 类型1（基础定位）：10.1%
- 类型2（带描述的特征定位）：29.5%
- 类型3（区域描述）：30.2%
- 类型4（层级分类）：30.3%

虽然类型3和类型4占比不低，但模型在第一阶段已经形成了输出定位格式的"习惯"。

### 2. 训练轮数不足

**当前配置**：`num_epochs: 3`

**问题**：
- 3个epoch可能不足以让模型学习新的任务格式
- 模型需要"忘记"定位格式，学习纯文本输出

### 3. 学习率可能偏小

**当前配置**：`learning_rate: 0.00005`（第一阶段的一半）

**问题**：
- 学习率太小可能导致模型更新不够，难以学习新的任务格式
- 对于多任务学习，可能需要更大的学习率来适应不同任务

### 4. 数据采样顺序

**问题**：
- 如果训练时定位任务和文本任务交替出现，模型可能混淆
- 需要确保模型能区分不同任务的输出格式

## 解决方案

### 方案1：增加训练轮数（推荐）

```yaml
training:
  num_epochs: 5  # 从3增加到5
  learning_rate: 0.00008  # 稍微提高学习率
```

**理由**：给模型更多时间学习新的任务格式

### 方案2：调整学习率策略

```yaml
training:
  learning_rate: 0.0001  # 恢复到第一阶段的学习率
  warmup_steps: 100  # 增加预热步数
  lr_scheduler:
    type: "cosine"
    warmup_ratio: 0.15  # 增加预热比例
```

**理由**：让模型有足够的更新幅度来学习新任务

### 方案3：任务平衡采样（重要）

在数据加载时，确保每个batch中不同类型任务的比例均衡：

```python
# 在CervicalDataset中添加任务类型标签
# 在DataLoader中使用BalancedBatchSampler
```

**理由**：避免模型偏向某一种任务格式

### 方案4：增加任务类型提示

在用户输入中明确任务类型：

```python
# 类型3：明确提示是描述任务
user_text = "<image>\n请用文字描述图中这个区域<region0>的特征"

# 类型4：明确提示是分类任务
user_text = "<image>\n请回答<region0>的细胞层级来源是什么（只回答层级来源的名称）"
```

**理由**：帮助模型区分不同任务

### 方案5：使用不同的损失权重（高级）

为不同类型任务设置不同的损失权重：

```python
def compute_loss(self, model, inputs, return_outputs=False, **kwargs):
    # 根据任务类型调整损失权重
    task_type = inputs.get('task_type', 'type1')
    base_loss = model(...).loss
    
    if task_type in ['type3', 'type4']:
        # 文本生成任务的损失权重更大
        loss = base_loss * 1.5
    else:
        loss = base_loss
    
    return loss
```

**理由**：强调文本生成任务的重要性

### 方案6：分阶段训练（最彻底）

1. **第一阶段**：只训练类型1和类型2（定位任务）
2. **第二阶段A**：继续训练类型1和类型2，同时加入类型3和类型4，但使用较小的学习率
3. **第二阶段B**：只训练类型3和类型4，使用正常学习率

**理由**：逐步引入新任务，避免任务混淆

## 总结

**核心问题**：模型混淆了任务类型，将文本生成任务（类型3、类型4）当成了定位任务（类型1、类型2），导致输出格式错误。

**主要原因**：
1. 第一阶段只学习了定位任务，形成了输出定位格式的习惯
2. 第二阶段训练轮数不足，无法充分学习新任务格式
3. 学习率可能偏小，模型更新不够

**推荐方案**：
1. ✅ 增加训练轮数到5-7个epoch
2. ✅ 适当提高学习率到0.00008-0.0001
3. ✅ 确保训练数据格式正确
4. ✅ 增加评估频率，及时发现问题
